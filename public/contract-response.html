Timestamp Format
+01:00 vs UTC Z		 ACCEPTED
Either Format		 The backend uses native ECMAScript standard ISO 8601 parsing (new Date(timestamp)). Both 2026-09-21T08:52:14.000+01:00 and Z are accepted and normalized into uniform ISO storage. No firmware clock conversion needed.
Offline Buffered Events
offlineBuffered: true		 ACCEPTED
Historical Preserved		 When replaying queued SPIFFS logs with offlineBuffered: true, the backend respects the event's timestamp for check-in time and punctuality calculations (late flag based on 09:00:00 AM of that day). It will never overwrite with "received now".
Evidence Photo Linkage
Correlating Camera with PIN		 ENHANCED
Exact Correlation		 Crucial Enhancement: The backend now returns "attendanceId": "ATT_..." and "eventId": "ATT_..." in the /api/attendance/checkin response. The ESP32-CAM should include attendanceId or eventId in the multipart POST to /api/attendance/evidence. If absent, fallback correlates to that user's latest check-in.
Commands-in-Telemetry
Piggyback on 30s heartbeat		 APPROVED
Optimal Architecture		 Piggybacking commands on POST /api/devices/telemetry response avoids maintaining separate polling timers on the ESP32 and prevents Wi-Fi socket exhaustion.
Command Queue Depth & Batching SPECIFIED
Max 3 per heartbeat		 The backend limits the commands array to 1 to 3 items per response. Terminal should execute sequentially or one per cycle.
Acknowledgment for Command Results CONFIRMED
Explicit {"ok": true, "ack": true}		 Fire-and-forget is not recommended for biometrics. When the terminal posts to /api/devices/commands/result, the backend returns an explicit 200 JSON ack before the terminal marks the command cleared from EEPROM.
Retry Policy for Permanent Errors SINGLE-REPORT
Report once & drop		 For permanent hardware errors (slot_full, duplicate_finger, sensor_timeout), terminal reports status: "error" once and drops the command. The backend marks the job failed in the dashboard and alerts the admin.
Command Result Endpoint Path CONFIRMED
/api/devices/commands/result		 Dedicated endpoint created, tested, and active. Handles both dashboard-directed commands and standalone terminal-initiated enrollments.
Terminal-Initiated (On-Device Menu) Enrollments SUPPORTED
Same endpoint		 Send to /api/devices/commands/result with "source": "terminal" and omit commandId (or pass null). The backend assigns and records the slot.

3. Critical Missing Parts Identified & Recommended Safeguards

Firmware Caution (Preventing Lockups & Flash Wear):
  • Command Deduplication: Since telemetry poll happens every 30s, if the terminal takes 45 seconds to scan a finger, the same commandId might arrive in the next heartbeat. The terminal firmware must keep an active in_progress_command_id variable so it does not re-trigger an ongoing scan.
  • Optical Sensor Timeout (SMF V1.7): When executing ENROLL_FINGERPRINT, set an explicit hardware timeout of 25 seconds on the fingerprint reader. If no finger is placed, return status: "error", errorReason: "sensor_timeout" so the terminal LCD returns to the default ready screen.
  • Slot 0 Protection: As correctly noted in your draft, slot 0 is strictly reserved for "No Match". The backend validates slotNumber >= 1 on all operations.
