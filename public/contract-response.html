Engineering Notice to Firmware Developers: If only telemetry was working during initial bench testing, this contract details why and confirms the full fixes deployed:
  1. Check-in Unmapped Slots & Array Payloads: DY50 fingerprint scans transmit optical slotNumber. Previously, if the slot was unmapped or if the terminal transmitted a JSON array [{...}] from SPIFFS flash, the server returned an ambiguous result without LCD feedback. The backend now accepts raw objects, raw arrays, or wrapped batches, and returns immediate LCD messages (e.g., "WELCOME, JOHN!" or "SLOT NOT FOUND").
  2. ESP32-CAM Evidence Linkage: Previously the photo endpoint required userId. ESP32-CAM firmware often only has attendanceId returned from check-in. The backend now correlates photos using attendanceId directly without requiring redundant user ID extraction.
  3. Flexible Casing: All endpoints accept both standard camelCase (e.g. deviceId, slotNumber) and C-struct snake_case (e.g. device_id, slot_number).

1. Complete Endpoint Summary & Matrix

Function Endpoint & Method What Firmware Sends What Backend Returns
1. Telemetry & Heartbeat
Every 30 seconds		 POST
/api/devices/telemetry		 Terminal status, RSSI, battery %, heap free bytes, LCD text lines. 200 OK with server time, heartbeat interval, and piggybacked command queue.
2. Attendance Check-In
On finger scan / PIN key		 POST
/api/attendance/checkin		 slotNumber (DY50 optical) OR userId (keypad), deviceId, timestamp. Supports SPIFFS burst replay. 201 Created with attendanceId, displayMessage for LCD/OLED, and user details.
3. Camera Evidence
Triggered on PIN / Audit		 POST
/api/attendance/evidence		 Multipart JPEG file, with attendanceId (from check-in response) and deviceId. 201 Created with storage verification and photo linkage acknowledgment.
4. Command Execution Report
After enrollment or deletion		 POST
/api/devices/commands/result		 Execution status (success/error), type, commandId, slotNumber, or errorReason. 200 OK explicit {"ok": true, "ack": true} before terminal clears task from EEPROM.

2.1 Endpoint 1: Telemetry & Heartbeat Polling

URL: https://<HOST>/api/devices/telemetry
Method: POST | Headers: Content-Type: application/json | Frequency: Every 30 seconds

Request Payload (Firmware → Cloud)
// Both camelCase and snake_case keys are supported
{
  "deviceId": "DEV_TERM_01",              // [REQUIRED] string: Unique terminal MAC or hardware ID
  "wifiStatus": "Connected",               // [OPTIONAL] "Connected" | "Disconnected"
  "rssi": -58,                             // [OPTIONAL] number: Signal strength in dBm (-30 to -90)
  "ipAddress": "192.168.1.102",            // [OPTIONAL] string: Current LAN IP
  "macAddress": "24:0A:C4:B8:3A:1E",       // [OPTIONAL] string: ESP32 Wi-Fi MAC
  "powerStatus": "AC",                     // [OPTIONAL] "AC" | "Battery"
  "batteryStatus": 95,                     // [OPTIONAL] number: Battery charge percentage (0-100)
  "voltage": "4.15V",                      // [OPTIONAL] string: ADC voltage readout
  "esp32Heap": "284 KB Free / 520 KB",     // [OPTIONAL] string: ESP.getFreeHeap()
  "pendingRecords": 0,                     // [OPTIONAL] number: Count of offline records in SPIFFS
  "firmwareVersion": "AttendX-FW v2.4.1",  // [OPTIONAL] string: Embedded build tag
  "maxSlots": 300,                         // [OPTIONAL] number: DY50 capacity (default 300)
  "enrolledFingerprints": 2,               // [OPTIONAL] number: Stored templates count in DY50
  "lcdText": [                             // [OPTIONAL] array of 2-4 strings for LCD verification
    "** ATTENDX TERMINAL **",
    "Ready for Scan...",
    "Time: Synced",
    "Net: CONNECTED"
  ]
}
Response Payload (Cloud → Firmware) — HTTP 200 OK
{
  "ok": true,
  "success": true,
  "deviceId": "DEV_TERM_01",
  "serverTime": "2026-09-24T18:30:00.000Z",           // ISO 8601 UTC timestamp for ESP32 RTC sync
  "terminalStatus": "ACKNOWLEDGED",
  "nextHeartbeatIntervalSeconds": 30,                 // Recommended loop sleep duration (seconds)
  "activeEnrolledFingerprints": 2,
  "commands": [                                       // Array of 0 to 3 pending commands to execute
    {
      "commandId": "cmd_enroll_9021",                 // Unique ID to send back in Section 2.4
      "type": "ENROLL_FINGERPRINT",                   // "ENROLL_FINGERPRINT" | "DELETE_FINGERPRINT"
      "userId": "USR001"                              // User to assign to scanned slot
    }
  ]
}

2.2 Endpoint 2: Attendance Check-In (Fingerprint & Keypad PIN)

URL: https://<HOST>/api/attendance/checkin
Method: POST | Headers: Content-Type: application/json

Request Payload: Optical Fingerprint Scan (DY50 Match)
{
  "deviceId": "DEV_TERM_01",                     // [REQUIRED] string: Terminal identifier
  "slotNumber": 2,                               // [REQUIRED for DY50] number: Slot (1-300) matched by DY50
  "authMode": "fingerprint",                     // [REQUIRED] "fingerprint"
  "timestamp": "2026-09-24T08:52:14.000+01:00",  // [REQUIRED] ISO string or numeric epoch seconds
  "offlineBuffered": false                       // [OPTIONAL] boolean: true if replayed from SPIFFS flash
}
Request Payload: Keypad PIN Entry
{
  "deviceId": "DEV_TERM_01",
  "userId": "USR001",                            // [REQUIRED for Keypad] string: Student/Staff ID (e.g. "USR001")
  "authMode": "pin",                             // [REQUIRED] "pin"
  "timestamp": "2026-09-24T08:55:00.000Z",
  "offlineBuffered": false
}
Request Payload: SPIFFS Offline Burst Replay (Multi-Record Array)
[
  { "deviceId": "DEV_TERM_01", "slotNumber": 1, "timestamp": "2026-09-24T08:42:00.000Z", "offlineBuffered": true },
  { "deviceId": "DEV_TERM_01", "slotNumber": 2, "timestamp": "2026-09-24T08:49:10.000Z", "offlineBuffered": true },

]

  "success": true,

  "userName": "Amina Yusuf",

  "lateMinutes": 0,
  "displayMessage": "WELCOME, AMINA!",               // [READY FOR LCD] Direct text string for 16x2/20x4 LCD

  "success": false,

Method: POST | Headers: Content-Type: multipart/form-data (or application/json with base64)

Multipart Form-Data Fields (ESP32-CAM → Cloud)
Field Name Type Required? Description
attendanceId (or eventId) Text string RECOMMENDED The exact attendanceId returned in the Section 2.2 check-in response. Accurately links photo to check-in log.
deviceId (or device_id) Text string Optional Terminal ID, e.g. "DEV_TERM_01".
userId (or user_id) Text string Optional Student ID (e.g. "USR003"). If omitted, cloud automatically resolves it via attendanceId!

3. Firmware Implementation Guidelines & Hardware Safeguards

Crucial ESP32 Firmware Rules:
  • Command Deduplication: If biometric scanning takes 40 seconds, the same command might re-appear in the next 30-second telemetry response. Store an active in_progress_cmd_id so the DY50 does not restart an active scan.
  • DY50 25-Second Sensor Timeout: Never block the ESP32 main loop indefinitely while waiting for finger placement. Set a 25-second countdown. If no finger is detected, post status: "error", errorReason: "sensor_timeout" and restore the default LCD screen.
  • Zero Retries on Dropped Photos: If an ESP32-CAM photo upload encounters a Wi-Fi drop mid-stream, do not retry or lock the terminal. The backend safely retains the check-in and logs evidenceStatus: "upload_dropped".
  • Slot 0 Guard: DY50 Slot 0 is strictly reserved by hardware for "Search / No Match". All valid user slots are 1 through 300.

3.1 Ready-to-Test Terminal cURL Commands

Test each endpoint directly from your computer terminal before flashing the ESP32:

# 1. Test Telemetry Heartbeat:
curl -X POST http://localhost:3000/api/devices/telemetry \
  -H "Content-Type: application/json" \
  -d '{"deviceId":"DEV_TERM_01","rssi":-55,"batteryStatus":96,"powerStatus":"AC","lcdText":["AttendX Ready","Scan Finger"]}'

# 2. Test Fingerprint Check-in (Slot #2):
curl -X POST http://localhost:3000/api/attendance/checkin \
  -H "Content-Type: application/json" \
  -d '{"deviceId":"DEV_TERM_01","slotNumber":2,"authMode":"fingerprint"}'

# 3. Test Keypad PIN Check-in (User USR001):
curl -X POST http://localhost:3000/api/attendance/checkin \
  -H "Content-Type: application/json" \
  -d '{"deviceId":"DEV_TERM_01","userId":"USR001","authMode":"pin"}'

# 4. Test Command Execution Result (Success):
curl -X POST http://localhost:3000/api/devices/commands/result \
  -H "Content-Type: application/json" \
  -d '{"deviceId":"DEV_TERM_01","commandId":"cmd_test","type":"ENROLL_FINGERPRINT","status":"success","slotNumber":5}'
